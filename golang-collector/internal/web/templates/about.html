Centralized Lightweight Collaborative Intrusion Detection System (CIDS)

Berbasis log RouterOS MikroTik dan algoritma Isolation Forest

Agentless

Tidak ada perangkat lunak tambahan di router. Sistem hanya memanfaatkan fasilitas Remote Syslog bawaan RouterOS (UDP 514), sehingga beban komputasi router tetap rendah.

Terpusat & Lightweight

Seluruh analisis machine learning dilakukan pada satu server pusat menggunakan algoritma berkompleksitas rendah, cocok untuk lingkungan UMKM dengan sumber daya terbatas.

Kolaboratif

Serangan yang terdeteksi pada satu node otomatis diblokir di semua node MikroTik melalui mekanisme Threat Intelligence Sharing — pertahanan kolektif.

Formula Isolation Forest

Liu, Ting & Zhou (2008) — unsupervised anomaly detection

Prinsip dasar

Data anomali lebih mudah diisolasi oleh pemisahan acak dibandingkan data normal, sehingga berada pada kedalaman pohon yang lebih dangkal — panjang lintasan h(x) kecil.

Skor anomali

s(x, n) = 2−E[h(x)] / c(n)

  • E[h(x)] — rata-rata panjang lintasan x pada seluruh pohon ({{index $d "n_estimators"}} pohon)
  • c(n) — normalisasi: rata-rata panjang lintasan pada Binary Search Tree berukuran n

Faktor normalisasi

c(n) = 2H(n−1) − 2(n−1)/n

H(i) ≈ ln(i) + 0.5772156649 (konstanta Euler)

Interpretasi

  • • s → 1 : sangat anomali (lintasan pendek, mudah diisolasi)
  • • s → 0.5 : tidak dapat dibedakan dari normal
  • • s → 0 : sangat normal

Implementasi scikit-learn

Sistem memakai decision_function(x) yang merupakan transformasi dari s(x,n): nilai negatif = anomali, positif = normal. Ambang keputusan mengikuti kalibrasi parameter contamination = {{index $d "contamination"}} (estimasi proporsi anomali pada data).

Preprocessing & Tingkat Keyakinan

Normalisasi fitur — StandardScaler

z = (x − μ) / σ

Setiap fitur distandarkan (rata-rata 0, deviasi 1) agar fitur berskala besar (mis. total_requests) tidak mendominasi fitur rasio (0–1). Parameter μ dan σ disimpan bersama model agar inferensi konsisten.

Keyakinan dua-faktor (confidence)

kepastian_skor = min(0.5 + |skor − T| × 2, 1.0)
kecukupan_data = min(n_aktivitas / {{index $d "confidence_full_n"}}, 1.0)
keyakinan = kepastian_skor × kecukupan_data

T = ambang anomali ({{index $d "anomaly_threshold"}}). Skor yang jauh dari ambang DAN didukung data yang cukup menghasilkan keyakinan tinggi. Ini mencegah pemblokiran berdasarkan 1–2 log saja.

Decision Engine (nilai aktif saat ini)

Izinkan skor ≥ {{index $d "anomaly_threshold"}}
Monitor skor < {{index $d "anomaly_threshold"}}, syarat blokir belum terpenuhi
Blokir skor < {{index $d "block_score"}} DAN keyakinan ≥ {{index $d "block_confidence"}}

Gerbang ganda (skor + keyakinan) dirancang konservatif: mengutamakan presisi tinggi / false positive rendah agar trafik pelanggan tidak terblokir keliru. Operator tetap dapat melakukan override manual (whitelist/blacklist). Admin dapat menyesuaikan seluruh ambang ini dari halaman Decision Engine tanpa me-restart sistem.

Metrik Evaluasi Sistem

Accuracy  = (TP + TN) / (TP + TN + FP + FN)
Precision = TP / (TP + FP)
Recall    = TP / (TP + FN)
F1-Score  = 2 × (Precision × Recall) / (Precision + Recall)
FPR       = FP / (FP + TN)

TP = serangan terdeteksi benar; FP = trafik normal salah dituduh; TN = normal dikenali normal; FN = serangan yang lolos. Evaluasi dilakukan dengan skenario trafik berlabel (ground truth) melalui skrip make evaluate: trafik latar beragam, brute force, port scan, dan flood menggunakan blok IP TEST-NET (RFC 5737).

Selain metrik klasifikasi, sistem diukur pada: waktu respons deteksi (syslog pertama → vonis pertama), efektivitas blokir otomatis, waktu sinkronisasi blacklist antar node, serta penggunaan CPU/RAM router dan server.
